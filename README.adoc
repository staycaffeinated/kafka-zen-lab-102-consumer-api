= kafka-zen-lab-102-consumer-api

Spring Boot Kafka consumer that ingests click-stream events produced by
`kafka-zen-lab-101-traffic-simulator`, maps them to domain events, and stores them.

== Overview

[cols="1,3"]
|===
|Concern |Detail

|Runtime
|Spring Boot 4 / Java 21

|Messaging
|Apache Kafka (Spring Kafka)

|Architecture
|Hexagonal (Ports & Adapters) + Clean Architecture layers

=== What It Does

1. Listens on `kafka-zen.lab-101.traffic-simulator.click-event.received`
2. Deserialises JSON into a `ClickEventMessage` subtype (discriminated by `eventType`)
3. Maps the message to a domain `ClickEvent`
4. Passes the event to `ClickEventProcessingService`, which persists it via `ClickEventStore`
5. Acknowledges the Kafka offset (manual ack)
6. On failure: retries 3x with 1 s back-off, then routes to the DLQ

=== Message Format

All messages use Jackson JSON. The type discriminator field is `eventType`.

[source,json]
----
// ProductViewedEventMessage
{
  "eventId": "evt-001",
  "eventType": "product.viewed",
  "timestamp": "2026-01-01T12:00:00Z",
  "userId": "usr-42",
  "sessionId": "sess-xyz",
  "correlationId": "corr-abc",
  "partitionKey": "usr-42",
  "product": { ... },
  "context": { ... }
}

// ProductAddedToCartEventMessage
{
  "eventId": "evt-002",
  "eventType": "cart.item.added",
  "timestamp": "2026-01-01T12:01:00Z",
  "userId": "usr-42",
  "sessionId": "sess-xyz",
  "correlationId": "corr-abc",
  "partitionKey": "usr-42",
  "productId": "prod-999",
  "metadata": { "quantity": 2 }
}
----

Deserialisation is configured via `spring.json.value.default.type` to
`ClickEventMessage`; Jackson resolves the concrete subtype using `@JsonSubTypes`.

=== Error Handling

`KafkaConsumerConfiguration` registers a `DefaultErrorHandler` bean that Spring
Boot auto-wires into the listener container factory.

[cols="1,2"]
|===
|Setting |Value

|Retry attempts
|3

|Back-off interval
|1 000 ms (fixed)

|Recovery action
|Route raw bytes to `CLICK_EVENT_DLQ` via a dedicated producer factory

|DLQ partition selection
|`-1` (Kafka chooses partition)
|===

NOTE: The DLQ producer factory is not exposed as a bean to avoid shadowing
Spring Boot's auto-configured `ProducerFactory<Object,Object>`.

== Developer Guide

=== Prerequisites

* Java 21 (defined in `.java-version`)
* Gradle 8.13 or higher (or use the wrapper)
* Docker (for Kafka and SonarQube)

=== First Steps

Create the Gradle wrapper if not present:

[source,shell]
----
gradle wrapper
----

=== Common Tasks

==== Compile and test

[source,shell]
----
./gradlew build
----

==== Build with coverage and Sonar

Update `gradle.properties` with your SonarQube coordinates, then:

[source,shell]
----
./gradlew clean build sonar
----

==== Change the Java version

Edit `.java-version` in the project root. Default is `21`.

==== Build a Docker image

[source,shell]
----
./gradlew jibDockerBuild
----

==== Run in Docker

[source,shell]
----
# Build the image first
./gradlew jibDockerBuild

# Launch via Compose (starts the app; connect to an external Kafka broker)
cd docker
docker-compose up -d
----

NOTE: The `docker/docker-compose.yml` starts only the application container. You need a running Kafka broker accessible at `localhost:9092` (or configure `spring.kafka.bootstrap-servers` via an environment variable).

==== Check for dependency updates

[source,shell]
----
./gradlew dependencyUpdates
----

==== Run only architecture tests

[source,shell]
----
./gradlew test --tests zen.lab.consumer.ArchitectureTest
----

== Extending the Application

=== Adding a New Event Type

1. Add a new `eventType` value to `Schema` if needed.
2. Create a concrete `ClickEventMessage` subclass (annotate with `@JsonSubTypes.Type` on `ClickEventMessage`).
3. Add the corresponding domain event record implementing `ClickEvent`.
4. Handle the new message type in `ClickEventMessageMapper.toDomain()`. The sealed-interface `switch` will be a compile error if the branch is missing.
5. Update `ClickEventProcessingService` or dispatch to a new use case as required.

=== Replacing `InMemoryClickEventStore`

`InMemoryClickEventStore` is a stub that logs the event ID and discards the payload. To persist events:

1. Implement `ClickEventStore` in a new class (e.g., in `adapters.edge.outbound.persistence`).
2. Annotate it with `@Component` (or register it in a `@Configuration` class).
3. Remove or qualify the stub bean to avoid ambiguity.
4. Add integration tests covering the new implementation.

=== Adding a Custom Validator

Validators follow the pattern in `adapters.edge.inbound.validation`:

1. Define a constraint annotation implementing `@Constraint(validatedBy = ...)`.
2. Implement `ConstraintValidator<YourAnnotation, YourType>`.
3. Externalise the default message in `ValidationMessages.properties`.
4. Apply the annotation to fields, method parameters, or type uses.
