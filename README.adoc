= kafka-zen-lab-102-consumer-api

Spring Boot Kafka consumer that ingests click-stream events produced by
`kafka-zen-lab-101-traffic-simulator`, maps them to domain events, and stores them.

== Overview

[cols="1,3"]
|===
|Concern |Detail

|Runtime
|Spring Boot 4 / Java 21

|Messaging
|Apache Kafka (Spring Kafka)

|Architecture
|Hexagonal (Ports & Adapters) + Clean Architecture layers

|Build
|Gradle multi-project with custom convention plugins

|Container
|Jib → OCI image (`kafka-zen-lab-102-consumer-api:latest`)
|===

=== What It Does

1. Listens on `kafka-zen.lab-101.traffic-simulator.click-event.received`
2. Deserialises JSON into a `ClickEventMessage` subtype (discriminated by `eventType`)
3. Maps the message to a domain `ClickEvent`
4. Passes the event to `ClickEventProcessingService`, which persists it via `ClickEventStore`
5. Acknowledges the Kafka offset (manual ack)
6. On failure: retries 3× with 1 s back-off, then routes to the DLQ

== Architecture

----
Inbound Adapters              Application Layer               Outbound Adapters
──────────────────────────── ──────────────────────────────  ─────────────────────────────
ClickEventMessageConsumer ──► MessageConsumerUseCase (port)   ClickEventStore (port)
ClickEventMessageMapper       ClickEventProcessingService ──► InMemoryClickEventStore (impl)
                              (service)
----

Implements `ClickEvent`. JSON `eventType = "product.viewed"`.

Additional fields:

[cols="1,1,3"]
|===
|Field |Type |Description

|`product`
|`Product`
|Full product snapshot at view time

|`context`
|`Context`
|Page context at view time
|===

Builder:

[source,java]
----
ProductViewedEvent event = ProductViewedEvent.builder()
    .eventId("evt-001")
    .eventType("product.viewed")
    .timestamp(Instant.now())
    .userId("usr-42")
    .sessionId("sess-xyz")
    .correlationId("corr-abc")
    .product(product)
    .context(context)
    .build();

== Kafka Reference

=== Topics

[cols="1,2,1"]
|===
|Constant |Topic Name |Purpose

|`Schema.Topics.CLICK_EVENT_RECEIVED`
|`kafka-zen.lab-101.traffic-simulator.click-event.received`
|Primary inbound topic

|`Schema.Topics.CLICK_EVENT_DLQ`
|`kafka-zen.lab-101.traffic-simulator.click-event.received.dlq`
|Dead-letter queue for unprocessable messages
|===

Both topics are bootstrapped on startup by `KafkaTopicBootstrapper`.

=== Message Format

All messages use Jackson JSON. The type discriminator field is `eventType`.

[source,json]
----
// ProductViewedEventMessage
{
  "eventId": "evt-001",
  "eventType": "product.viewed",
  "timestamp": "2026-01-01T12:00:00Z",
  "userId": "usr-42",
  "sessionId": "sess-xyz",
  "correlationId": "corr-abc",
  "partitionKey": "usr-42",
  "product": { ... },
  "context": { ... }
}

// ProductAddedToCartEventMessage
{
  "eventId": "evt-002",
  "eventType": "cart.item.added",
  "timestamp": "2026-01-01T12:01:00Z",
  "userId": "usr-42",
  "sessionId": "sess-xyz",
  "correlationId": "corr-abc",
  "partitionKey": "usr-42",
  "productId": "prod-999",
  "metadata": { "quantity": 2 }
}
----

Deserialisation is configured via `spring.json.value.default.type` to
`ClickEventMessage`; Jackson resolves the concrete subtype using `@JsonSubTypes`.

=== Error Handling

`KafkaConsumerConfiguration` registers a `DefaultErrorHandler` bean that Spring
Boot auto-wires into the listener container factory.

[cols="1,2"]
|===
|Setting |Value

|Retry attempts
|3

|Back-off interval
|1 000 ms (fixed)

|Recovery action
|Route raw bytes to `CLICK_EVENT_DLQ` via a dedicated producer factory

|DLQ partition selection
|`-1` (Kafka chooses partition)
|===

NOTE: The DLQ producer factory is not exposed as a bean to avoid shadowing
Spring Boot's auto-configured `ProducerFactory<Object,Object>`.

* Java 21 (defined in `.java-version`)
* Gradle 8.13 or higher (or use the wrapper)

Create the Gradle wrapper if not present:

== Extending the Application

=== Adding a New Event Type

1. Add a new `eventType` value to `Schema` if needed.
2. Create a concrete `ClickEventMessage` subclass (annotate with `@JsonSubTypes.Type`).
3. Add the corresponding domain event implementing `ClickEvent`.
4. Handle the new message type in `ClickEventMessageMapper.toDomain()`.
5. Update `ClickEventProcessingService` or dispatch to a new use case as required.

=== Replacing `InMemoryClickEventStore`

`InMemoryClickEventStore` is a stub. To persist events, implement `ClickEventStore`
and register it as a Spring bean. Remove or qualify the stub bean.
